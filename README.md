# インターネット図書館システム

## 概要

在籍する専門学校のチーム開発演習の授業で制作した、インターネット図書館のWebシステムです。

## 開発経緯

開発演習では、以下のような架空の状況が与えられました。

> 
> 
> 
> 某地区には小学校(8校)や中学校(2校)が運営されており、もっとも離れた学校間は約50kmあります。それぞれの学校の図書館（図書室）では、以下に示す三つの問題を抱えています。
> 
> 1. そもそも図書館がない学校があるが、予算がなく手が打てない
> 2. 校内に図書館はあるが、新しい書籍を購入する予算がない
> 3. 生徒の読書機会（読書意欲）が顕著に減少
> 
> そこであなた方は、インターネット上に各学校が利用できる図書館があれば、これらの問題を解決することができるのではと考えました。
> 

この状況を基に、以下のような要件が事前に定義された状態で与えられました。

要件1:    地域の学校間で本が共有される
要件2:   校内の図書を管理する
要件3:   各学校の図書館の管理システムも兼ねる
要件4:   他校へ本を配送する際の配送もシステム化範囲に含む
要件5:   講読意欲を活性化させる

また、開発期間終盤から、以下の要件についても「事前の告知なし」という想定で追加されました。

追加要件:   貸出禁止期間を設定する

これらの要件を満たしながら、さらに細かな要件や仕様は各チームに一任される形で開発がスタートしました。

 ①貸出・返却画面は、司書アカウントからのみアクセス可能。生徒アカウントから貸出処理、返却画面へアクセスはできない。
 
 ②書籍の現物が無ければ貸出も返却もできない。
 ※現時点（2026年3月）では、バーコードリーダーによる書籍の識別を実装していないため、書籍の貸し出し状況によっては技術的に可能となってしまっています。ですが、本来は書籍の現物を①で示した場所まで持っていき、司書ないし図書係の前で貸出・返却処理を行うことになります。
 
 ③他校の本を借りる際は、予約処理を挟む必要がある。取り寄せ処理は予約処理として扱っている。

## ✨ こだわり・学習のポイント

1. 書籍の貸出・返却時の仕様
    
    書籍の貸出・返却時は、時間的・技術的な制約から、バーコードリーダーではなく書籍ID（ISBNとは別にシステム内で用意したユニークな管理ID）を入力させる方式としています。
    
2. 予約処理/他校からの取り寄せ処理の仕様
    
    予約の優先順位の判断には、FIFO方式を採用しています。また、他校の本を取り寄せる場合、たとえ取り寄せる本に一件も予約が入っていなかったとしても、書籍予約でその本を取り寄せ、現地で貸出と返却の処理をする仕様としました。取り寄せ処理を予約処理として扱う事で、「取り寄せ要求」と「予約要求」の優先度を判断する過程を省略し、処理の安定性と開発工程削減を実現しました。また、貸出期限の一部が配送に要した時間で消費されることが原因で、学校の配送距離によっては他校よりも貸出期限が短くなってしまうという不公平な状況の発生を防ぎました。
    
3. CSRF対策
    
    予約処理やログイン・ログアウト処理といった重要な処理において、CSRF攻撃を想定したトークン方式のチェックを徹底しました。これは、生コードである程度規模のある開発が可能な今回の演習において、情報処理安全確保支援士の対策で学習したCSRF攻撃とその対策を実践したかったためです。当初はワンタイムトークンを使用する予定でしたが、セッション管理の問題から、ログイン時に発行したトークンを再利用する方式に変更しています。
    
4. 利用者の行動をなるべく変えない仕様
    
    予約した図書を貸し出す際、他の生徒が予約者になりすまし、その図書を受け取りに来る可能性を考えました。顔写真付きの学生証等を持参させることも考えましたが、予約を受け取りに行く度に身分証明の物品を持参させることは、「要件5:   講読意欲を活性化させる」を阻害させる要因になるほか、顔写真付きの証明物が無い場合、新たに学校（クライアント）側に対して学生証等の発行を強いる可能性があると感じました。
    そこで、システムの機能でそれを補い、クライアントに要求する行動を最小限にしようと考えました。具体的には、学生が図書を予約した際、予約者に対してシステム内で一意の予約番号を発行し、予約受取貸出時にその番号を入力させる仕様としました。生徒用マイページから予約番号は閲覧できます。
    
5. 配送管理での誤操作を防ぐ仕組み
    
    配送管理画面では、指定された学校を基に、その学校に対して搬入する図書、搬出する図書をシステム内で自動判別し、それぞれのリストを表示するようにしています。配送員は、搬入・搬出扱いの図書を記憶することなく、リストのチェックボックスを選択し、チェックを入れた図書の物理的な搬入・搬出のみを行ないます。これにより、配送員が誤って図書を搬入済み扱いにしたり、搬出扱いでない図書を搬出してしまったりするリスクを減らしています。
    
6. 生成AIの扱い
    
    生成AIに一任せず、一度自力でコードを書いてからフィードバックを受け、改善したものに対して再度フィードバックを受けるサイクルを繰り返しました。これにより、Web開発における認証処理、セッション管理、トランザクション処理、排他制御といった処理の概要を掴み、プロトタイプを6~7割ほど自力で組み立てる能力を磨きました。
